# N5 — Multiset budget signatures for Nielsen witnesses

**Status:** candidate — exact finite classification must be recomputed.

## Research object

Study balanced decompositions of Nielsen tuples using exact finite subgroup data only.
For a split \(I \sqcup J\), write

\[
A = H_I(g), \qquad B = H_J(g), \qquad K = A \cap B.
\]

The primary budget record is the prime-factor multiset triple

\[
\mathbf B_{\mathrm{ms}}(g;I,J)
=
\bigl(\operatorname{PF}(|A|),\operatorname{PF}(|B|),\operatorname{PF}(|K|)\bigr),
\]

where \(\operatorname{PF}(m)\) is the multiset of prime factors of \(m\), with
multiplicity. The relative budget may additionally record the exact index
multisets

\[
\Delta_A = \operatorname{PF}([A:K]),\qquad
\Delta_B = \operatorname{PF}([B:K]).
\]

No logarithms, floating-point thresholds, square roots, transcendental
functions, or limiting arguments belong in the certificate kernel.

The exact product identity

\[
|A\cap B|\,|AB| = |A|\,|B|
\]

lifts to the multiset identity

\[
\operatorname{PF}(|A\cap B|)
\uplus
\operatorname{PF}(|AB|)
=
\operatorname{PF}(|A|)
\uplus
\operatorname{PF}(|B|).
\]

This identity is the first budget-calculus invariant to preserve in code and
tests.

## First gate: define the minimizer, then recompute

The earlier exploratory work used a logarithmic normalized intersection score.
Changing the objective to a multiset/index budget can change which balanced
split is selected. Therefore **none of the previous five-regime or five-value
classification is inherited automatically**.

Before any theorem or finite-domain claim is added:

1. specify a deterministic total ordering (or explicitly stated partial order
   plus tie-break) on split budget records;
2. specify the canonical minimizing split independently of presentation order;
3. enumerate the complete ordered testbed
   \(\mathrm{Ni}(S_6,(2,2,6,6))/S_6\);
4. record all candidate split budgets, not only the selected split;
5. recompute witness certificates from the newly selected minimizer;
6. compare the resulting classification with the previous logarithmic census.

A disagreement with the old minimizer is data, not a failure condition.

## Witness certificates

For the degree-6 base case, the intended witness layer is certificate-based:

- \`FixedPoint\`: a singleton orbit of a minimizing half-subgroup;
- \`PairBlocks\`: preservation of a \(2+2+2\) block system;
- \`TripleBlocks\`: preservation of a \(3+3\) block system;
- \`CrossBlocks\`: the two minimizing halves certify different block types;
- \`Containment\`: one minimizing half-subgroup is contained in the other;
- \`Other\`: explicit fallback until exhaustive computation proves it unreachable.

The certificate payload must include the actual fixed element, block partition,
or subgroup-containment witness as appropriate. Classification predicates and
their checking procedures are separate objects.

## Ordered Hurwitz state space

The base testbed has ordered conjugacy data \((2,2,6,6)\). The exact
reachability target is therefore the label-preserving braid action on that
ordered state space.

A full \(B_4\) Hurwitz move may permute conjugacy classes across tuple
positions and hence leave the ordered state space. No full-\(B_4\)
transitivity claim on the 12 ordered inner classes is in scope unless an
enlarged state space is defined and exhaustively certified separately.

For the ordered testbed, the desired finite certificate is a BFS adjacency
list under a declared label-preserving move set, with traversal order and
canonical class identifiers committed as data.

## Candidate claims and non-claims

Current candidate claims are deliberately narrow:

- the multiset/index budget is an exact, finite arithmetic object suitable for
  deterministic instrumentation;
- block/containment witness labels can be backed by finite certificates in the
  \(S_6\) testbed;
- the complete base-case census is feasible and is the first evidentiary gate.

The following are **not established**:

- novelty of Hurwitz/Nielsen moves or short finite-horizon walks;
- preservation of the old logarithmic five-value classification under the new
  minimizer;
- a general implication from low budget overlap to wreath/imprimitive
  structure;
- a full-\(B_4\) orbit theorem on the ordered \((2,2,6,6)\) state space;
- higher-rank wreath/flag forcing;
- any cryptographic hardness claim.

## Reduction-calculus boundary

The conversation that motivated this candidate also explored reductions as
mathematical objects. That is a separate programme boundary.

Cryptographic game, advantage, witness, and reduction semantics are
consumer-owned by \`crypto-composer\`; \`finite-math-kernels/proof_records\`
remains domain-neutral. N5 may reuse generic proof-record and exact-arithmetic
infrastructure, but it must not move domain-specific reduction semantics into
the shared kernel merely to support this candidate.

A future domain-neutral budgeted reduction calculus requires an independent
specification and more than one genuine consumer.

## Planned finite artifacts

The first reproducible run should commit:

- canonical representatives of every ordered inner class;
- every balanced split for every representative;
- exact subgroup orders \(|A|,|B|,|A\cap B|,|AB|\);
- prime-factor multisets and index multisets;
- the deterministic minimizer key and selected split;
- the witness label plus its certificate payload;
- the ordered-state-space adjacency list and BFS traversal certificate;
- a canonical digest of the complete result set.

Finite observations should enter \`research/ledger.json\` only after replayable
code, parameters, and hashes exist.

## Literature gate

Before any novelty promotion, perform a dated, query-recorded search covering:

- Hurwitz actions and Nielsen classes;
- braid-orbit computation and component certification;
- subgroup-intersection and index invariants;
- imprimitive/wreath subgroup classification in symmetric groups;
- prior normalized or discrete overlap/entanglement observables on generating
  tuples;
- finite-horizon perturbation/random-walk analyses on Hurwitz or Nielsen
  graphs.

Classical machinery must remain attributed as classical even when reused in a
new experimental interface.

## Stop conditions

Stop and revise rather than promote if:

- the multiset minimizer is not fully specified;
- the new minimizer changes the base classification and the manuscript still
  quotes the old one;
- a claimed orbit action does not preserve the declared state space;
- certificate output omits the underlying fixed element, partition, or
  containment evidence;
- exact-kernel code introduces floats or transcendental primitives;
- a literature search finds the proposed invariant or classification already
  in equivalent form.
