# Pentagon boundary and finite oracle

## N2-T04 — the associator boundary closes

In any algebra over a commutative ring, define
[
[x,y,z]=x(yz)-(xy)z.
]
Then
[
[a,b,c]d+[a,bc,d]+a[b,c,d]-[a,b,cd]-[ab,c,d]=0.
]

**Proof.** Expand the five terms:
[
egin{aligned}
[a,b,c]d &= (a(bc))d-((ab)c)d,\
[a,bc,d] &= a((bc)d)-(a(bc))d,\
a[b,c,d] &= a(b(cd))-a((bc)d),\
-[a,b,cd] &= -a(b(cd))+(ab)(cd),\
-[ab,c,d] &= -(ab)(cd)+((ab)c)d.
end{aligned}
]
Every parenthesized four-letter word occurs once with each sign. ∎

The five terms are precisely the signed edge differences around the five
binary parenthesizations of (abcd). Thus the additive boundary always
closes, even when individual edges are nonzero. Non-associativity is retained
as edge data rather than erased.

## Oracle boundary

The Python experiment instantiates the scalar Cayley–Dickson construction
over (mathbb F_p) and exhausts basis quadruples. The Lean oracle does not
trust that implementation: it accepts an explicit multiplication tensor over
(mathbb Z/pmathbb Z), recomputes all products and associators, and checks
the pentagon boundary independently.

The self-check (`lake exe oracle-selfcheck`, run in CI after the build) exercises a
non-associative instance. `NoveltyLab/Fixture.lean` is generated by
`experiments/n2/lean_fixture.py` from the Python experiment. It contains the
8×8×8 Cayley–Dickson structure tensor over 𝔽₅ and three quadruples: a basis
witness with two nonzero edges, and two dense inputs with all five edges
nonzero. For each case, `NoveltyLab/SelfCheck.lean` requires:

- the boundary closes (N2-T04);
- the five edge terms equal the values Python computed (independent replay);
- each edge term equals the difference of the two parenthesizations it
  joins, so a wrong sign or factor order in any single term fails even though
  the sum might still close;
- some edge is nonzero, and in discriminating cases all five are;
- mutation controls are killed. Negating edge i breaks the boundary exactly
  when edge i ≠ 0. Moving the outer factor of [a,b,c]d or a[b,c,d] to the
  other side breaks it.

These mutations of `Oracle.lean` were each confirmed to fail the self-check:
- dropping the sign of [a,b,cd];
- d[a,b,c] in place of [a,b,c]d;
- [bc,a,d] in place of [a,bc,d];
- (ba) in place of (ab) inside [ab,c,d];
- a transposed tensor;
- a globally negated associator, which leaves the boundary closed and is
  caught only by the vertex and replay checks.

The scalar table remains only as an associative sanity case.

This is an executable oracle, not yet a formal proof that an input tensor is
an octonion algebra or that (p) is prime. Those are separate certificate
obligations. N2-T04 itself is proved above for every algebra, so the oracle is
a regression and evidence-replay layer.
